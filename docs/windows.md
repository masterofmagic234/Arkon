# Windows-версия

Портативная сборка Windows x64 содержит `AcornHunter.exe`, расположенный рядом `AcornHunter.pck`, инструкцию и лицензии. В официальном Windows EXE Godot 4.7.2 ANGLE связан статически; отдельные графические DLL не требуются. Распакуйте весь архив в папку; отдельная установка движка, кодеков, Python или FFmpeg не требуется. Выбор графики в главном меню сохраняется между запусками.

Поддерживаемая платформа — Windows 10/11 x64, процессор с SSE4.2 и видеодрайвер с OpenGL 3.3 либо Direct3D 11 с поддержкой OpenGL ES 3 через комплектный ANGLE. Compatibility сохраняется; Vulkan для этой сборки не требуется. Это требования платформы, а не подтверждённый замером минимальный компьютер для каждого уровня. 8 ГБ ОЗУ можно взять как начальный рекомендуемый запас для проверки; FPS и достаточность конкретной старой видеокарты нужно измерять на ней.

Слабые встроенные GPU и младшие дискретные карты получают экономный профиль; более мощные карты — баланс или качество. Вручную профиль можно сменить через «ГРАФИКА». В парке отдельно ограничиваются 3D пиксели, мелкая растительность и свет; в погоне — целевой размер изображения машин и декоративная работа; в пиццерии — реальные источники света и эффекты. Частота физики, число противников и правила боя сохраняются.

Управление перечислено в `tools/windows157/README.txt`, который попадает в сборку как `README.txt`. Мобильные клавиши не требуются: используются WASD, мышь и клавиатурные действия. В оконном режиме Windows работает обычная кнопка закрытия окна; неподдерживаемый полноэкранный хоткей не рекламируется.

Сборка выпускается через `.github/workflows/windows_build.yml`. Ubuntu экспортирует настоящий Windows release EXE/PCK из точного исходного дерева и подготавливает проверенные Theora-катсцены. Следующая задача Windows скачивает тот же артефакт и проверяет PE, PCK, контрольные суммы и версии. Сначала запускается обычное неизменённое приложение; отдельно проверяются его окно, меню и настоящие события мыши и клавиатуры Windows.

Для подробных проверок уровней и управления используются временные копии того же release EXE и PCK с идентичными контрольными суммами. Только в тестовой папке файл `override.cfg` выбирает внешнюю стартовую сцену проверки. Производственные ресурсы PCK сохраняются побайтно; проверочные скрипты и этот файл в сборку не входят. Такой способ нужен потому, что официальный release-шаблон Godot 4.7 запрещает CLI `--script` и `--main-pack`.

Ручной запуск workflow может повторно проверить готовый артефакт по его ID и точным SHA исходников, дерева и checkout. При этом сохраняются исходные размер, SHA-256 ZIP и номер сборки, а новый SHA проверочных скриптов записывается отдельно. Повторное использование разрешается только при изменении перечисленных файлов CI и документации; изменения игровых ресурсов требуют нового экспорта. Независимые проверки окна, кадров уровней и управления сохраняют результаты даже при соседнем сбое; итоговая проверка требует успеха каждой.

На Windows запускается обычный драйвер Compatibility со встроенным ANGLE из официального EXE. На сервере CI проверяется фактически выбранный программный адаптер Direct3D 11. Проверяются реальные кадры трёх уровней в двух профилях и непустое изображение машины; тестовые драйверы в папку игры не подмешиваются. Такие проверки подтверждают работу Windows-пакета и рендеринга, но не измеряют FPS обычной видеокарты.

При повторной проверке исходного артефакта инструкция внутри ZIP остаётся исходной: текущие уточнения про встроенный ANGLE в неё не подменяются. SHA исходного пакета и нового проверочного кода записываются отдельно.

Сборка не имеет платного сертификата Authenticode. Целостность файлов подтверждается `build-manifest.json`, а целостность скачанного ZIP — каноническим SHA-256 GitHub Actions. Инструкция, лицензия Godot и его сторонние уведомления включены в пакет.
